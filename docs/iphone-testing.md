# Real iPhone offline verification

Status: on 2026-10-17 the owner reported all cases in the chat's step-by-step iPhone walkthrough passed, including offline force-close/relaunch and reconnect/desktop synchronization. An additional conflict-resolution case also passed. See [the acceptance results](validation.md). The broader checklist below remains useful for future releases; scenarios beyond that walkthrough are not automatically marked verified. Desktop tests remain supporting evidence only. Record iPhone model, iOS version, build, timezone and date when available.

1. Serve a production build over HTTPS. Open it in Safari online, wait for **Ready for offline use**, and use Share → Add to Home Screen. Launch the installed app once online and confirm offline readiness there too.
2. Enable Airplane Mode and explicitly turn Wi-Fi off. Launch from the Home Screen. Confirm the UI opens and says Offline.
3. Tap Start Charging once. Confirm the saved-on-device message and start timestamp. Try rapid repeated taps; only one session may exist.
4. Switch apps, lock the phone and leave it suspended. Return and confirm elapsed time derives from the original timestamp.
5. Force-close PlugTime while offline. Relaunch from the Home Screen. The active session must still be present. After at least one minute from the original start, tap Stop Charging and confirm a completed history record. Separately verify an immediate start/stop is discarded, Cancel charge immediately undoes a start during the first minute, cancelling after a minute asks for confirmation, and Delete last charge removes a completed charge only after confirmation. None of the discarded charges should count in statistics.
6. Force-close and relaunch again offline. Confirm start/end timestamps, elapsed time, estimated energy and CAD cost remain correct. Record any missing shell assets or data.
7. Edit the end to a later date, including a session crossing midnight. Confirm corrections persist after relaunch. Try an end before the start and verify it is rejected without changing history.
8. Add a past session with no end time. Confirm it says Incomplete and does not become the live charging timer. Complete it after the fact. Delete a synthetic session and verify the confirmation and persistent removal.
9. Change charging/rate defaults and verify existing sessions keep their assumptions while new sessions use new values. Inspect monthly/yearly totals and rounding. Test a DST-crossing interval and reject a nonexistent/repeated input time.
10. Export JSON and CSV offline using the installed app. Save to Files and inspect the actual file contents on a second device. Include unsynchronized sessions, defaults and deletion tombstones in JSON. Confirm CSV omits incomplete estimates rather than inventing zero consumption.
11. Request persistent storage. Record whether it is granted. Test accessible labels, touch targets, keyboard entry, light/dark mode, rotation and safe areas. Do not clear real site data to test eviction; use a separate test installation.
12. Test an application update while a charge is active and while the editor is open. Open/resume online to check automatically, or use Statistics / Settings → App updates → Check for app updates. The prompt appears at the top and installation must wait. After stopping and closing the editor, install it and confirm data survives. Also install from another window while this view has an editor open: this view must retain its editor until explicitly reloaded.

Phase 2 additions: expired Access authentication must leave offline recording available, show sign-in separately from offline status, and resume synchronization after user sign-in. Test interrupted uploads, retries of the same mutation, two-device conflicts, deletion convergence, edits during upload and initial full-history download on a fresh installation.

Phase 3 automated/operational validation passed for JSON restoration round trips, duplicate imports, Toronto DST conversion, malformed rows and reviewed reconciliation. See [validation](validation.md) and [migration/recovery](importing.md). Preserve the prior owner-reported acceptance evidence above.

Additional iPhone check for the new import flow: export a synthetic test backup to Files, then choose it using Statistics / Settings → Import JSON backup while offline. Review counts before adding anything, save the pre-import download, relaunch and repeat the import to confirm no duplicates. Confirm a backup differing from an existing test record is blocked and local edits remain. Reconnect and verify cloud conflicts require explicit resolution. Use a separate test installation or independent pre-test export; do not clear real history. This new file-picker/download flow has Chromium coverage but has not yet been reported as tested on the physical iPhone.

An older installed version places **Install update** at the bottom of the current page. To receive the improved updater, open that installation online, finish any charge/editor and scroll below Cloud backup on the Charging screen. Tap Install update when shown. If it has not appeared, fully close and reopen the installed app online, allow time for the download, and check again. Keep the installation and its local records; clearing site data is unnecessary for the normal update flow. Record the physical result rather than assuming a successful desktop update proves iPhone behavior.
